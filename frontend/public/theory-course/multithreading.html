Multithreading

What is Multithreading?

A thread is the smallest unit of execution in a program. By default, Java runs on one thread (the main thread). Multithreading means running multiple threads concurrently so work can overlap.

This improves responsiveness (UI doesn’t freeze) and can use multiple CPU cores for faster processing.

  • Games: render, input, physics simultaneously
  • Servers: handle many clients at once
  • Apps: background tasks without blocking UI
  • Data processing: split work across cores

Creating a Thread — Extend Thread

Extend Thread and override run(). Call start() to begin execution in a new thread.

Use this only when you don’t need to extend any other class.

public class MyThread extends Thread { private String name; public MyThread(String name) { this.name = name; } @Override public void run() { for (int i = 1; i <= 5; i++) { System.out.println(name + " — step " + i); } } } public class Main { public static void main(String[] args) { MyThread t1 = new MyThread("Thread-A"); MyThread t2 = new MyThread("Thread-B"); t1.start(); t2.start(); } }
Exam Point: Always call start(), not run().

Creating a Thread — Runnable

Runnable is preferred because Java supports single inheritance. It lets your class extend another class and still run on a thread.

public class MyTask implements Runnable { private String taskName; public MyTask(String taskName) { this.taskName = taskName; } @Override public void run() { for (int i = 1; i <= 4; i++) { System.out.println(taskName + " executing step " + i); } } } public class Main { public static void main(String[] args) { Thread t1 = new Thread(new MyTask("Download")); Thread t2 = new Thread(new MyTask("Upload")); t1.start(); t2.start(); } }

Way 3: Lambda

Since Runnable is a functional interface, you can use a lambda for the shortest syntax.

public class Main { public static void main(String[] args) { Thread t1 = new Thread(() -> { for (int i = 1; i <= 3; i++) System.out.println("Task 1 — step " + i); }); Thread t2 = new Thread(() -> { for (int i = 1; i <= 3; i++) System.out.println("Task 2 — step " + i); }); t1.start(); t2.start(); } }

Thread Lifecycle

A thread moves through well-defined states from creation to completion.

NEW → RUNNABLE → RUNNING → (BLOCKED/WAITING) → TERMINATED
NEW: created, not started RUNNABLE: ready for CPU RUNNING: executing BLOCKED/WAITING: waiting for lock/resource TERMINATED: finished

Useful Thread Methods

These methods help manage thread execution, naming, priority, and pausing.

Thread t = new Thread(() -> System.out.println("Running")); t.start(); t.getName(); t.setName("MyThread"); t.getPriority(); t.setPriority(Thread.MAX_PRIORITY); t.isAlive(); Thread.currentThread().getName(); Thread.sleep(1000); // pause current thread
Thread t2 = new Thread(() -> { for (int i = 1; i <= 3; i++) { System.out.println("Tick " + i); try { Thread.sleep(1000); } catch (InterruptedException e) { System.out.println("Thread interrupted"); } } }); t2.start();

join() — Wait for a Thread

join() makes the current thread wait until another thread finishes. Use it when you need a result before continuing.

Thread t1 = new Thread(() -> { System.out.println("Downloading..."); try { Thread.sleep(2000); } catch (InterruptedException e) {} System.out.println("Download complete!"); }); t1.start(); t1.join(); System.out.println("Now processing the downloaded file.");

The Race Condition Problem

A race condition happens when multiple threads access and modify shared data without proper synchronization.

Operations like count++ are not atomic. Internally they read the value, add 1, and write it back. Two threads can interleave these steps and overwrite each other.

The result is unpredictable and may differ each run even with the same inputs.

public class Counter { int count = 0; void increment() { count++; } } public class Main { public static void main(String[] args) throws InterruptedException { Counter counter = new Counter(); Thread t1 = new Thread(() -> { for (int i = 0; i < 1000; i++) counter.increment(); }); Thread t2 = new Thread(() -> { for (int i = 0; i < 1000; i++) counter.increment(); }); t1.start(); t2.start(); t1.join(); t2.join(); System.out.println("Count: " + counter.count); } }

synchronized — The Fix

synchronized allows only one thread at a time inside the protected method or block, preventing data corruption.

When a thread enters a synchronized section, it acquires a lock. Other threads must wait until the lock is released.

Use a synchronized block when you want to lock only a small part of the method for better performance.

public class Counter { int count = 0; synchronized void increment() { count++; } }
public class Counter2 { int count = 0; Object lock = new Object(); void increment() { synchronized (lock) { count++; } } }

volatile — Visibility Between Threads

volatile ensures that all threads read the latest value from main memory instead of using a cached copy.

It guarantees visibility of changes but does not make compound operations atomic.

Use it for simple stop flags or state checks, not for increments or multi-step updates.

public class FlagExample { volatile boolean running = true; public void stop() { running = false; } public void run() { while (running) { System.out.println("Working..."); } System.out.println("Stopped."); } }

AtomicInteger — Thread-safe Counter

AtomicInteger provides lock-free, thread-safe updates for counters.

Methods like incrementAndGet() run atomically using CPU-level compare-and-swap, so no updates are lost.

It is faster than synchronized for simple counters and avoids contention for small shared numeric state.

import java.util.concurrent.atomic.AtomicInteger; public class SafeCounter { AtomicInteger count = new AtomicInteger(0); void increment() { count.incrementAndGet(); } }

Deadlock

A deadlock happens when two or more threads each hold a lock the other needs. Everyone waits forever, so no progress is made.

This usually occurs when locks are acquired in different orders across threads.

  • Always acquire locks in a consistent order across the codebase
  • Keep synchronized blocks short and avoid nested locks when possible
  • Use timeout-based locks from java.util.concurrent when appropriate
Object lockA = new Object(); Object lockB = new Object(); Thread t1 = new Thread(() -> { synchronized (lockA) { System.out.println("T1 holds A, waiting for B"); try { Thread.sleep(100); } catch (InterruptedException e) {} synchronized (lockB) { System.out.println("T1 got both locks"); } } }); Thread t2 = new Thread(() -> { synchronized (lockB) { System.out.println("T2 holds B, waiting for A"); try { Thread.sleep(100); } catch (InterruptedException e) {} synchronized (lockA) { System.out.println("T2 got both locks"); } } });

wait() and notify()

wait() makes a thread pause and release the lock so other threads can enter the synchronized block.

notify() wakes one waiting thread; notifyAll() wakes all of them. These calls must happen inside synchronized code.

Use a while loop to recheck the condition after waking to avoid spurious wakeups.

public class SharedBox { private int value; private boolean hasValue = false; public synchronized int consume() throws InterruptedException { while (!hasValue) { wait(); } hasValue = false; notify(); return value; } public synchronized void produce(int val) throws InterruptedException { while (hasValue) { wait(); } value = val; hasValue = true; System.out.println("Produced: " + val); notify(); } }
SharedBox box = new SharedBox(); Thread producer = new Thread(() -> { for (int i = 1; i <= 5; i++) { try { box.produce(i); } catch (InterruptedException e) {} } }); Thread consumer = new Thread(() -> { for (int i = 1; i <= 5; i++) { try { int val = box.consume(); System.out.println("Consumed: " + val); } catch (InterruptedException e) {} } }); producer.start(); consumer.start();

ExecutorService — Thread Pool

ExecutorService manages a pool of reusable threads and schedules tasks for you.

This avoids the overhead of creating a new Thread for each task and gives better control over concurrency.

Always call shutdown() to stop accepting new tasks and allow the JVM to exit cleanly.

import java.util.concurrent.ExecutorService; import java.util.concurrent.Executors; ExecutorService executor = Executors.newFixedThreadPool(3); for (int i = 1; i <= 6; i++) { int taskId = i; executor.submit(() -> { System.out.println("Task " + taskId + " running on " + Thread.currentThread().getName()); }); } executor.shutdown();
Executors.newFixedThreadPool(4); Executors.newSingleThreadExecutor(); Executors.newCachedThreadPool();

Common Mistakes

These errors cause missing threads, wrong results, or programs that never exit.

t.run(); // wrong // t.start(); // t1.start(); // System.out.println(result); // t1.join(); executor.submit(task); // executor.shutdown();
