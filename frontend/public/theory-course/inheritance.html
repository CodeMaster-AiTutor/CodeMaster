Inheritance

What is Inheritance?

Inheritance is a fundamental mechanism in Object-Oriented Programming that allows a new class to acquire the properties and behaviors of an existing class. The class that inherits is called the subclass (or child), and the class being inherited from is the superclass (or parent). This relationship promotes code reusability because you define common attributes once in the parent and share them across all children. It also establishes an "is-a" relationship, such as "a Dog is an Animal".

Animal (parent) ├── Dog (child) ├── Cat (child) └── Bird (child)

In this hierarchy, Dog, Cat, and Bird all share the common traits defined in Animal, but they can also have their own unique features.

The Problem Without Inheritance

Without inheritance, you would have to copy-paste the same code into multiple classes. If you had 10 different types of animals, you would repeat the `eat()` and `sleep()` methods 10 times. This duplication makes the code hard to maintain because if you need to change how `eat()` works, you have to update it in 10 different places. Inheritance solves this by keeping the common logic in one central place.

public class Dog { String name; int age; void eat() { System.out.println(name + " is eating."); } void bark() { System.out.println(name + " is barking."); } } public class Cat { String name; int age; void eat() { System.out.println(name + " is eating."); } void meow() { System.out.println(name + " is meowing."); } }

Notice how `name`, `age`, and `eat()` are identical in both classes. This redundancy is a clear sign that inheritance should be used.

extends — Creating a Child Class

The `extends` keyword is used to create a subclass that inherits from a superclass. When `Dog extends Animal`, the `Dog` class automatically gets all non-private fields and methods from `Animal`. You can then add new fields (like `breed`) and new methods (like `bark`) that are specific only to dogs. This keeps the `Animal` class clean and general, while the `Dog` class focuses on dog-specific logic.

public class Animal { String name; int age; public Animal(String name, int age) { this.name = name; this.age = age; } public void eat() { System.out.println(name + " is eating."); } public void sleep() { System.out.println(name + " is sleeping."); } @Override public String toString() { return name + " (age " + age + ")"; } } public class Dog extends Animal { String breed; public Dog(String name, int age, String breed) { super(name, age); this.breed = breed; } public void bark() { System.out.println(name + " is barking!"); } } public class Cat extends Animal { boolean isIndoor; public Cat(String name, int age, boolean isIndoor) { super(name, age); this.isIndoor = isIndoor; } public void meow() { System.out.println(name + " says meow!"); } }

super — Accessing the Parent

The `super` keyword refers to the direct parent class of the current object. It is most commonly used to call the parent's constructor to ensure that inherited fields are initialized correctly. You can also use it to call a method in the parent class that has been overridden in the child class. This is useful when you want to keep the parent's behavior and just add a little bit more to it, rather than replacing it entirely.

public Dog(String name, int age, String breed) { super(name, age); this.breed = breed; } @Override public void eat() { super.eat(); System.out.println("...and asking for more!"); }

Method Overriding

Method overriding happens when a child class provides a specific implementation for a method that is already defined in its parent. This allows the child to modify or completely replace the behavior inherited from the parent. For example, all animals make a sound, but a dog barks and a cat meows. The method signature (name, return type, and parameters) must be exactly the same as in the parent class.

public class Animal { String name; public Animal(String name) { this.name = name; } public void makeSound() { System.out.println(name + " makes a sound."); } } public class Dog extends Animal { public Dog(String name) { super(name); } @Override public void makeSound() { System.out.println(name + " barks: Woof!"); } } public class Cat extends Animal { public Cat(String name) { super(name); } @Override public void makeSound() { System.out.println(name + " meows: Meow!"); } }

@Override Annotation

The `@Override` annotation is a safety feature that tells the compiler you intend to override a method. If you make a mistake, like checking the spelling or parameter list, the compiler will generate an error to alert you. While it is optional, using it is considered a best practice because it makes your code easier to read and less prone to bugs. It clearly signals to other developers that this method replaces one from the parent class.

Polymorphism with Inheritance

Inheritance enables polymorphism, which means you can treat different child objects as instances of their parent class. You can create an array of `Animal` references that holds `Dog`, `Cat`, and `Bird` objects. When you call a method like `makeSound()` on these references, Java automatically executes the correct version for the actual object (e.g., the Dog's bark). This makes your code flexible and scalable, as you can add new animal types without changing the loop logic.

Animal a1 = new Dog("Rex"); Animal a2 = new Cat("Whiskers"); a1.makeSound(); a2.makeSound(); Animal[] animals = { new Dog("Rex"), new Cat("Whiskers") }; for (Animal a : animals) { a.makeSound(); }

Even though the reference type is `Animal`, the actual behavior is determined by the object type at runtime.

instanceof — Checking the Real Type

The `instanceof` operator checks if an object is an instance of a specific class or subclass. This is useful when you have a parent reference (like `Animal`) but need to access child-specific methods (like `bark`). Before casting the object to `Dog`, you should always check `if (a instanceof Dog)` to avoid a `ClassCastException`. This ensures that your type conversions are safe and valid.

Animal a = new Dog("Rex"); System.out.println(a instanceof Animal); System.out.println(a instanceof Dog); System.out.println(a instanceof Cat); if (a instanceof Dog) { Dog d = (Dog) a; d.bark(); }

Rules of Overriding

Overriding is powerful but comes with strict rules to ensure consistency. The method name, return type, and parameter list must match the parent's method exactly. You cannot reduce the visibility of the method (e.g., making a public method private), but you can increase it. Also, methods marked as `final` or `static` cannot be overridden, as their behavior is fixed or belongs to the class rather than the instance.

Rule Details
Same name Must match parent method name exactly
Same parameters Same number and types
Same or wider access protected can become public, not private
Cannot override final final methods cannot be changed
Cannot override static Static methods are hidden, not overridden

Types of Inheritance in Java

Java supports several types of inheritance structures. Single inheritance is when a class extends one other class. Multilevel inheritance involves a chain, like `BabyDog extends Dog extends Animal`. Hierarchical inheritance is when one parent has multiple children, like `Cat` and `Dog` both extending `Animal`. However, Java does not support multiple inheritance (one class extending two classes) to avoid ambiguity and complexity.

Single: class Animal { } class Dog extends Animal { } Multilevel: class Animal { } class Mammal extends Animal { } class Dog extends Mammal { } Hierarchical: class Animal { } class Dog extends Animal { } class Cat extends Animal { } class Bird extends Animal { }

The lack of multiple inheritance is a design choice to keep the language simple and avoid the "Diamond Problem".

final — Preventing Inheritance or Overriding

The `final` keyword can be used to restrict inheritance features. If you mark a class as `final`, no other class can extend it (e.g., the `String` class). If you mark a method as `final`, no subclass can override it. This is useful when you want to guarantee that a specific behavior remains unchanged and secure across your entire application.

public final class MathUtils { public static int square(int n) { return n * n; } } public class Animal { public final void breathe() { System.out.println("Breathing..."); } }

Full Example: Employee Hierarchy

This example models a company structure with a base `Employee` class and specialized `Manager` and `Intern` subclasses. The `calculateSalary()` method is overridden to provide different logic for each role. The `Manager` gets a bonus, while the `Intern` gets a reduced salary. Using an array of `Employee` references allows us to process the entire payroll in a single loop, demonstrating polymorphism in action.

public class Employee { private String name; private int id; private double baseSalary; public Employee(String name, int id, double baseSalary) { this.name = name; this.id = id; this.baseSalary = baseSalary; } public String getName() { return name; } public int getId() { return id; } public double getBaseSalary() { return baseSalary; } public double calculateSalary() { return baseSalary; } @Override public String toString() { return String.format("[%d] %-12s Salary: $%.2f", id, name, calculateSalary()); } } public class Manager extends Employee { private double bonus; public Manager(String name, int id, double baseSalary, double bonus) { super(name, id, baseSalary); this.bonus = bonus; } @Override public double calculateSalary() { return getBaseSalary() + bonus; } } public class Intern extends Employee { public Intern(String name, int id, double baseSalary) { super(name, id, baseSalary); } @Override public double calculateSalary() { return getBaseSalary() * 0.6; } } Employee[] staff = { new Employee("Alice", 1, 50000), new Manager("Bob", 2, 50000, 15000), new Intern("Charlie", 3, 30000) }; for (Employee e : staff) { System.out.println(e); }

Common Mistakes

A frequent mistake is forgetting to call `super()` in the child constructor, which leads to compilation errors if the parent doesn't have a default constructor. Another error is trying to extend multiple classes, which Java forbids. Beginners also often confuse overriding with overloading, or forget that private fields are not directly accessible in the child class (you must use getters).

class Animal { public Animal(String name) { } } class Dog extends Animal { public Dog() { } } class Dog extends Animal, Pet { } class Dog extends Animal { void show() { System.out.println(name); System.out.println(getName()); } }

Practice Exercises

These exercises focus on building class hierarchies and understanding method overriding. Start by creating simple parent-child relationships and then add more complexity with multilevel inheritance. Pay attention to how constructors chain together using `super`. Testing your classes with polymorphic arrays will help reinforce the concept of treating different objects uniformly.

  • Create Vehicle → Car/Bike with extra fields and methods.
  • Create Shape → Circle/Square and override area().
  • Call super.eat() in a child and add extra behavior.
  • Create Animal → Mammal → Dog and add fields and methods at each level.
  • Create Shape → Circle/Rectangle/Triangle and override area().
  • Create Vehicle → Car → ElectricCar and override fuelType().
  • Try overriding a final method and observe the error.
  • Build Employee → Manager/Developer/Intern and override calculateSalary().
  • Use Employee[] and find the highest-paid.
