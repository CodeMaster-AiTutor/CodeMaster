OOP Intro

Why Programming Needed OOP

Procedural programs worked for small tasks, but modern systems (banking, reservations, e‑commerce) created software complexity: thousands of global variables, functions modifying unrelated data, and bugs that are hard to trace. OOP solves this by modeling real-world entities instead of just writing steps.

Core Idea of OOP

Real world is made of objects (Car, Student, Book, BankAccount). Each object has state (data) and behavior (actions).

// Student // State → name, age, marks // Behavior → study(), attendClass(), giveExam()

What is a Class

A class is a blueprint or template that defines what data an object will store and what actions it can perform. It is a design, not the real thing.

  • Building map → Class, Actual house → Object
  • Car design → Class, Actual car → Object
class Student { String name; int age; void study() { System.out.println(name + " is studying"); } }

This defines how a student looks and behaves; it does not create a student yet.

What is an Object

An object is a real instance created from a class.

Student s1 = new Student(); // create object s1.name = "Aayu"; s1.age = 20; s1.study(); // Output: Aayu is studying

Object Creation in Memory

On new:

  • Creates a reference variable (e.g., s1)
  • Allocates object memory on the heap
  • Links reference to that object

The variable holds the address, not the object itself.

Multiple Objects from Same Class

Student s1 = new Student(); Student s2 = new Student(); s1.name = "Rahul"; s2.name = "Priya"; // separate data, no overwrite

Fields and Methods

Fields (variables inside class) store object data; each object gets its own copy. Methods (functions inside class) define behavior and operate on fields.

class BankAccount { double balance; void deposit(double amt) { balance += amt; } }

Why OOP is Powerful

Without OOP, a bank program might have balance1, balance2, balance3… and withdraw1(), withdraw2(), withdraw3()… Impossible to manage. With OOP, define BankAccount once and create objects per customer — clean and scalable.

Real World Modeling

Real World → Class → Object Student → Student → Rahul Car → Car → Honda City Account → BankAccount → Account #1234

Interaction Between Objects

Objects communicate by calling each other’s methods. Example: an ATM object uses a BankAccount object to withdraw.

Basic Terminology Summary

  • Class → Blueprint
  • Object → Instance of class
  • Field → Data inside object
  • Method → Action of object
  • Reference → Variable storing object address

Procedural vs Object-Oriented Thinking

  • Procedural: What steps should the program follow?
  • OOP: What real-world things exist and what can they do?
Exam Point: Define class and object; give one example with state and behavior.
