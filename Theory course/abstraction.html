Abstraction

What is Abstraction?

Abstraction is the concept of hiding complex implementation details and showing only the essential features of an object. It allows you to focus on what an object does rather than how it does it. For example, when you drive a car, you know that pressing the gas pedal makes it go faster, but you don't need to understand the intricate mechanics of fuel injection or combustion. In Java, abstraction is achieved using abstract classes (0 to 100% abstraction) and interfaces (100% abstraction). It helps reduce complexity and increases security by preventing direct access to internal logic.

  • Abstract Class: Use when classes share a common identity ("is-a").
  • Interface: Use when unrelated classes share a capability ("can-do").

Abstract Classes

An abstract class is a class that cannot be instantiated on its own; it serves as a base for subclasses. It can contain both abstract methods (which have no body and must be implemented by the child) and concrete methods (which have a body and are inherited as-is). This allows you to define a template where some behavior is fixed (like `eat()`) and some is left for the child to decide (like `makeSound()`). Abstract classes are perfect for capturing common characteristics in a hierarchy, like `Animal` or `Vehicle`.

public abstract class Animal { protected String name; protected int age; public Animal(String name, int age) { this.name = name; this.age = age; } public abstract void makeSound(); public abstract String getType(); public void eat() { System.out.println(name + " is eating."); } @Override public String toString() { return getType() + ": " + name + " (age " + age + ")"; } } public class Dog extends Animal { public Dog(String name, int age) { super(name, age); } @Override public void makeSound() { System.out.println(name + " barks: Woof!"); } @Override public String getType() { return "Dog"; } }

Abstract Class Rules

Working with abstract classes requires following specific rules enforced by the compiler. You cannot create an object directly from an abstract class using `new`. If a class has even one abstract method, the class itself must be declared abstract. Subclasses must either implement all inherited abstract methods or be declared abstract themselves. These rules ensure that you never have an incomplete object in your system.

Rule Detail
Cannot instantiate new AbstractClass() is not allowed
Can have constructor Called via super() from child
Abstract methods No body, ends with ;
Concrete methods Fully implemented, inherited
Child must implement all Or be abstract itself

When to Use Abstract Class

Use an abstract class when you want to share code among several closely related classes. If you have fields (like `name` or `age`) that every child needs, an abstract class is the best place to define them. It is also useful when you want to define non-static or non-final fields, which interfaces cannot do. Essentially, use it when there is a strong "is-a" relationship, like "Dog is an Animal".

  • Classes share common fields and behavior.
  • You want to declare non-static or non-final fields.
  • You require access modifiers other than public (like protected).

What is an Interface?

An interface is a pure contract that defines a set of methods a class must implement. Unlike abstract classes, interfaces cannot hold state (instance fields) or constructors. They are used to define capabilities that can be shared across completely different class hierarchies, like `Drawable` or `Serializable`. A class "implements" an interface, promising to provide the actual code for all the methods defined in that contract.

public interface Drawable { void draw(); void resize(int factor); }

implements — Using an Interface

To use an interface, a class uses the `implements` keyword. This forces the class to provide a body for every method declared in the interface. In the example below, both `Circle` and `Square` implement `Drawable`, but they draw themselves in completely different ways. This loose coupling allows you to treat different objects uniformly based on what they can do, not just what they inherit from.

public class Circle implements Drawable { private int radius; public Circle(int radius) { this.radius = radius; } @Override public void draw() { System.out.println("Drawing circle with radius " + radius); } @Override public void resize(int factor) { radius *= factor; System.out.println("Circle resized. New radius: " + radius); } }

Multiple Interfaces

One of Java's most powerful features is that a class can implement multiple interfaces, effectively supporting multiple inheritance of type. This allows a single class, like `Document`, to be both `Printable` and `Saveable` at the same time. This is not possible with classes, where you can only extend one parent. This flexibility is key to designing modular and decoupled systems.

public interface Printable { void print(); } public interface Saveable { void save(); } public class Document implements Printable, Saveable { private String content; public Document(String content) { this.content = content; } @Override public void print() { System.out.println("Printing: " + content); } @Override public void save() { System.out.println("Saving: " + content); } }

default Methods (Java 8+)

Before Java 8, adding a new method to an interface would break every class that implemented it. To solve this, default methods were introduced. They allow you to add a method with a body to an interface, so existing classes don't need to change. This feature provides backward compatibility while allowing interfaces to evolve over time.

public interface Greeting { void greet(String name); default void greetAll(String[] names) { for (String name : names) greet(name); } } public class FormalGreeting implements Greeting { @Override public void greet(String name) { System.out.println("Good day, " + name + "."); } }

Interface Rules

Interfaces strictly separate definition from implementation. All variables declared in an interface are implicitly `public`, `static`, and `final` (constants). All methods are implicitly `public` and `abstract` (unless marked `default` or `static`). You cannot instantiate an interface directly because it has no constructor and is incomplete by definition.

Rule Detail
Methods Abstract by default
Fields public static final only
Cannot instantiate new Interface() not allowed
implements One class can implement many
default Concrete and can be overridden

Abstract Class vs Interface

Choosing between an abstract class and an interface is a common design decision. Use an abstract class when you need to share code (fields and methods) among related classes. Use an interface when you need to define a role or capability that unrelated classes can implement. A class can extend only one abstract class but can implement multiple interfaces.

Feature Abstract Class Interface
Instantiate ❌ No ❌ No
Methods Abstract + Concrete Abstract + default
Fields Any type public static final only
Constructor ✅ Yes ❌ No
Extends/Implements One class Multiple interfaces
Use when Shared code + is-a Shared contract + can-do

Full Example: Notification System

This example combines both concepts to build a flexible system. We use an abstract class `Notification` to handle the shared `recipient` and `message` fields. We use an interface `Schedulable` to add scheduling capability only to `EmailNotification`. This design allows `SMSNotification` to inherit the basics without being forced to implement scheduling logic it doesn't support.

public abstract class Notification { protected String recipient; protected String message; public Notification(String recipient, String message) { this.recipient = recipient; this.message = message; } public abstract void send(); public void log() { System.out.println("LOG: Notification to " + recipient); } } public interface Schedulable { void schedule(String dateTime); } public class EmailNotification extends Notification implements Schedulable { public EmailNotification(String recipient, String message) { super(recipient, message); } @Override public void send() { System.out.println("Email to " + recipient + ": " + message); log(); } @Override public void schedule(String dateTime) { System.out.println("Email scheduled for " + dateTime); } } public class SMSNotification extends Notification { public SMSNotification(String recipient, String message) { super(recipient, message); } @Override public void send() { System.out.println("SMS to " + recipient + ": " + message); log(); } }

Common Mistakes

A frequent mistake is trying to instantiate an interface or abstract class using `new`, which causes a compile-time error. Another issue is forgetting to implement all methods of an interface in a concrete class. Also, beginners often mistakenly think interface fields are instance variables, but they are actually static constants. The examples below highlight these pitfalls.

new Animal(); new Drawable(); class Circle implements Drawable { public void draw() { } } interface Shape { int width = 10; int getWidth(); }

Practice Exercises

These exercises challenge you to apply abstraction to real-world scenarios. Start by building a simple hierarchy using an abstract class. Then, introduce interfaces to add capabilities like "Resizable" or "Taxable" to specific classes. This hands-on practice will help you understand when to use "extends" versus "implements" in your own projects.

  • Create Shape → Circle/Rectangle and a Resizable interface.
  • Use abstract class for common fields and interface for capabilities.
  • Create Notification with Email/Push and Schedulable interface.
