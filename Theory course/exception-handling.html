Exception Handling

What is an Exception?

An exception is an unexpected event that disrupts the normal flow of a program. Unlike a syntax error, which prevents the code from compiling, an exception occurs while the program is running (runtime). Common examples include trying to divide by zero, accessing an invalid array index, or trying to read a missing file. If these events are not handled properly, the Java Virtual Machine (JVM) will abruptly terminate the program and print a stack trace. Exception handling allows you to catch these errors and respond gracefully instead of crashing.

int[] arr = {1, 2, 3}; System.out.println(arr[5]);

In the code above, accessing index 5 of a 3-element array causes an `ArrayIndexOutOfBoundsException`, crashing the program immediately.

try-catch

The `try-catch` block is the most basic mechanism for handling exceptions. You place the risky code (code that might throw an exception) inside the `try` block. If an exception occurs, the flow of control jumps immediately to the `catch` block, skipping the rest of the `try` block. The `catch` block contains the code to handle the error, such as logging a message or providing a fallback value. This prevents the program from terminating unexpectedly.

try { int result = 10 / 0; System.out.println(result); } catch (ArithmeticException e) { System.out.println("Error: " + e.getMessage()); } System.out.println("Program continues...");

Because the exception was caught, the final print statement executes normally, proving the program did not crash.

Multiple catch Blocks

A single piece of code can throw different types of exceptions, and you might want to handle each one differently. You can chain multiple `catch` blocks after a single `try` block to handle specific exception types. Java checks the catch blocks in order, from top to bottom, and executes the first one that matches the exception type. It is important to order them from most specific to most general (e.g., catch `ArithmeticException` before `Exception`) to avoid unreachable code errors.

public class Main { public static void main(String[] args) { String[] names = {"Alice", null, "Bob"}; int[] nums = {10, 20, 30}; for (int i = 0; i <= 4; i++) { try { String upper = names[i].toUpperCase(); int num = nums[i]; System.out.println(upper + " — " + num); } catch (NullPointerException e) { System.out.println("Null found at index " + i); } catch (ArrayIndexOutOfBoundsException e) { System.out.println("Index " + i + " out of bounds"); } } } }

In this loop, one iteration triggers a `NullPointerException` and another triggers an `ArrayIndexOutOfBoundsException`, but the loop continues processing the remaining items.

finally — Always Runs

The `finally` block is optional and follows the `try` and `catch` blocks. The code inside `finally` is guaranteed to execute whether an exception occurred or not, and whether it was caught or not. This makes it the perfect place for cleanup code, such as closing files, releasing database connections, or unlocking resources. Even if the `try` block has a `return` statement, the `finally` block will run before the method actually returns.

try { int result = 10 / 2; System.out.println("Result: " + result); } catch (ArithmeticException e) { System.out.println("Math error."); } finally { System.out.println("This always runs."); }

Common Built-in Exceptions

Java provides a rich hierarchy of built-in exceptions to cover most common error scenarios. Understanding these helps you identify bugs quickly. `ArithmeticException` usually involves math errors like division by zero. `NullPointerException` happens when you try to use a reference that points to nothing. `ArrayIndexOutOfBoundsException` means you went past the end of an array. `ClassCastException` occurs when you force an object into an incompatible type.

Exception Cause
ArithmeticException Divide by zero
NullPointerException Using null reference
ArrayIndexOutOfBoundsException Invalid array index
NumberFormatException Integer.parseInt("abc")
ClassCastException Invalid type cast
StackOverflowError Infinite recursion

throw — Manually Throwing an Exception

You can use the `throw` keyword to explicitly trigger an exception in your code. This is useful for enforcing business logic rules, such as preventing a bank withdrawal if funds are insufficient or rejecting a negative age input. When you throw an exception, you typically create a new instance of an exception class and pass a descriptive message. This stops the current method execution and signals the error to the calling code.

public class Student { private String name; private int age; public void setAge(int age) { if (age < 1 || age > 120) { throw new IllegalArgumentException("Invalid age: " + age); } this.age = age; } public void setName(String name) { if (name == null || name.trim().isEmpty()) { throw new IllegalArgumentException("Name cannot be empty."); } this.name = name; } }

throws — Declaring Exceptions

The `throws` keyword is used in a method signature to indicate that the method might throw one or more exceptions. This warns any code calling this method that it needs to be prepared to handle those exceptions. For "checked" exceptions (like `IOException`), using `throws` is mandatory if you don't handle the exception locally. It effectively passes the responsibility of handling the error up the call stack.

public int divide(int a, int b) throws ArithmeticException { if (b == 0) throw new ArithmeticException("Cannot divide by zero"); return a / b; }

Checked vs Unchecked Exceptions

Java distinguishes between two main types of exceptions: checked and unchecked. Unchecked exceptions (subclasses of `RuntimeException`) usually represent programming errors (like bugs in logic) and the compiler does not force you to handle them. Checked exceptions (subclasses of `Exception` but not `RuntimeException`) represent external failure conditions (like missing files or network issues) and the compiler requires you to handle them with try-catch or declare them with throws.

int[] arr = new int[3]; arr[5] = 10; public void readFile(String path) throws IOException { FileReader fr = new FileReader(path); }

Exception Hierarchy

All exceptions in Java inherit from the `Throwable` class. The two main branches are `Error` and `Exception`. `Error` represents serious system-level problems (like `OutOfMemoryError`) that applications should not try to catch. `Exception` is the parent of all checked and unchecked exceptions that your program might want to handle. `RuntimeException` is a special subclass of `Exception` for unchecked exceptions.

Throwable ├── Error │ └── StackOverflowError │ └── OutOfMemoryError └── Exception ├── IOException ├── SQLException └── RuntimeException ├── NullPointerException ├── ArithmeticException ├── IllegalArgumentException └── ArrayIndexOutOfBoundsException

Multi-catch (Java 7+)

If you have several exception types that require the exact same handling logic, you can combine them into a single `catch` block using the pipe (`|`) symbol. This feature, introduced in Java 7, reduces code duplication and makes the code cleaner. The exception parameter in a multi-catch block is implicitly final, meaning you cannot assign a new value to it. It is a great way to handle multiple related errors (like different types of database exceptions) in one place.

try { String s = null; int[] arr = new int[3]; s.length(); arr[10] = 1; } catch (NullPointerException | ArrayIndexOutOfBoundsException e) { System.out.println("Caught: " + e.getMessage()); }

Custom Exceptions

Sometimes the built-in Java exceptions don't accurately describe the error in your specific domain. In such cases, you can create your own custom exceptions by extending the `Exception` (for checked) or `RuntimeException` (for unchecked) class. This allows you to give your errors meaningful names like `InsufficientFundsException` or `InvalidUserException`. Custom exceptions can also store additional data, such as the amount of money that was missing.

public class InsufficientFundsException extends RuntimeException { private double amount; public InsufficientFundsException(double amount) { super("Insufficient funds. Needed: $" + amount); this.amount = amount; } public double getAmount() { return amount; } } public class InvalidAgeException extends Exception { public InvalidAgeException(int age) { super("Invalid age: " + age + ". Must be between 1 and 120."); } }

try-with-resources

The `try-with-resources` statement allows you to declare resources (like streams, sockets, or database connections) that should be closed automatically. Any object that implements `AutoCloseable` can be used here. Java ensures that the `close()` method is called on each resource at the end of the block, even if an exception occurs. This eliminates the need for verbose `finally` blocks just to close resources and prevents resource leaks.

try (FileReader fr = new FileReader("data.txt"); BufferedReader br = new BufferedReader(fr)) { String line; while ((line = br.readLine()) != null) { System.out.println(line); } } catch (IOException e) { System.out.println("File error: " + e.getMessage()); }

Full Example: Student Validation System

This comprehensive example demonstrates how to create a custom checked exception and use it for data validation. The `validate` method checks inputs and throws `InvalidStudentException` with specific messages if constraints are violated. The `main` method processes a list of raw data, catching and logging any validation errors while allowing the loop to continue for valid records. This is a common pattern in batch processing applications.

public class InvalidStudentException extends Exception { public InvalidStudentException(String message) { super(message); } } public class StudentValidator { public static void validate(String name, int age, double marks) throws InvalidStudentException { if (name == null || name.trim().isEmpty()) throw new InvalidStudentException("Name cannot be empty."); if (age < 1 || age > 120) throw new InvalidStudentException("Invalid age: " + age); if (marks < 0 || marks > 100) throw new InvalidStudentException("Marks out of range: " + marks); System.out.println("Valid student: " + name); } }

Common Mistakes

A very common mistake is catching the generic `Exception` class, which can hide bugs by catching everything, including unexpected runtime errors. Another bad practice is leaving a catch block empty ("swallowing" the exception), which makes debugging impossible since you never see the error. Using exceptions for normal control flow (like loop termination) is also discouraged because it is slow and confusing.

catch (Exception e) { } catch (ArithmeticException e) { } catch (Exception e) { } catch (Exception e) { System.out.println(e.getMessage()); }
