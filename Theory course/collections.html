Collections

What is the Collections Framework?

Arrays are fixed-size. Real programs need dynamic structures: unique sets, key-value maps, sorted data, fast lookups. Java’s Collections Framework provides these as ready-made structures.

It is a unified set of interfaces and classes that standardize how collections are stored, accessed, and iterated.

This makes code consistent and lets you swap implementations without changing the logic.

Main interfaces → List, Set, Map List: ordered, duplicates allowed Set: unique elements only Map: key-value pairs

List

A List is ordered, index-based, and allows duplicates.

Elements maintain insertion order, and you can access or update by index.

Lists are ideal when sequence matters, such as playlists, to‑do items, or maintaining a ranked order.

Common operations include get(index), set(index, value), and inserting at a specific position.

ArrayList (most commonly used)

Backed by a resizable array. Fast random access, slower insertions in the middle.

Random access is O(1) because elements are stored contiguously in memory.

Insertions or deletions in the middle require shifting elements, which is O(n).

Appends are fast, but resizing occasionally costs time due to copying.

import java.util.ArrayList; import java.util.List; List students = new ArrayList<>(); students.add("Alice"); students.add("Bob"); students.add("Charlie"); students.add("Alice"); System.out.println(students); // [Alice, Bob, Charlie, Alice] System.out.println(students.get(1)); // Bob System.out.println(students.size()); // 4 students.set(1, "Bobby"); students.remove("Charlie"); students.remove(0); System.out.println(students.contains("Alice")); for (String s : students) { System.out.println(s); }

LinkedList (fast insert/remove at ends)

Doubly linked list. Fast insert/remove at beginning or end, slower index access.

Each node stores data plus references to previous and next nodes.

Accessing by index requires traversal from the head or tail, so it is O(n).

Best for queue/deque style usage and frequent end insertions/removals.

import java.util.LinkedList; LinkedList tasks = new LinkedList<>(); tasks.add("Task A"); tasks.add("Task B"); tasks.addFirst("Urgent Task"); tasks.addLast("Low Priority"); System.out.println(tasks.getFirst()); System.out.println(tasks.getLast()); tasks.removeFirst(); System.out.println(tasks);

ArrayList vs LinkedList

Choose based on access pattern: frequent indexing vs frequent insert/delete.

If you need fast reads by index, choose ArrayList. If you need many inserts/removes near the ends, choose LinkedList.

In practice, ArrayList is preferred for most read-heavy workloads.

Get by index → ArrayList O(1), LinkedList O(n) Add at end → ArrayList O(1), LinkedList O(1) Add at start → ArrayList O(n), LinkedList O(1) Memory use → ArrayList less, LinkedList more Best for → ArrayList index access, LinkedList frequent inserts/deletes

Set

A Set stores unique elements only. Duplicates are ignored.

Sets are useful for membership checks, de-duplication, and maintaining uniqueness.

The definition of “duplicate” depends on equals() and hashCode() for that type.

Use Set when you care about uniqueness rather than order or position.

HashSet (fastest, no order)

Uses hashing for O(1) average insert and lookup. Does not guarantee order.

Ideal for fast membership checks like “has this ID been seen before?”.

Iteration order can change if the table resizes or the hash distribution changes.

import java.util.HashSet; HashSet cities = new HashSet<>(); cities.add("Delhi"); cities.add("Mumbai"); cities.add("Bangalore"); cities.add("Delhi"); System.out.println(cities); System.out.println(cities.size()); System.out.println(cities.contains("Mumbai")); cities.remove("Mumbai");

TreeSet (sorted)

Keeps elements sorted using a balanced tree. Slower than HashSet but ordered.

Insert and lookup are O(log n), but you get sorted iteration and range queries.

Elements must be comparable or you must provide a comparator.

import java.util.TreeSet; TreeSet scores = new TreeSet<>(); scores.add(75); scores.add(90); scores.add(60); scores.add(90); scores.add(85); System.out.println(scores); System.out.println(scores.first()); System.out.println(scores.last()); TreeSet names = new TreeSet<>(); names.add("Mango"); names.add("Apple"); names.add("Banana"); System.out.println(names);

LinkedHashSet (insertion order)

Maintains insertion order while keeping uniqueness. Slightly slower than HashSet.

Great when you need uniqueness plus predictable iteration order, such as removing duplicates while preserving input order.

import java.util.LinkedHashSet; LinkedHashSet languages = new LinkedHashSet<>(); languages.add("Java"); languages.add("Python"); languages.add("C++"); languages.add("Java"); System.out.println(languages);

Set Comparison

Choose a Set based on ordering and performance needs. HashSet is fastest, TreeSet keeps data sorted, and LinkedHashSet preserves insertion order.

Use HashSet for speed, TreeSet for sorted views and ranges, LinkedHashSet for consistent iteration order.

Order → HashSet none, TreeSet sorted, LinkedHashSet insertion Performance → HashSet fastest, TreeSet slower, LinkedHashSet slightly slower Nulls → HashSet one, TreeSet no, LinkedHashSet one Best for → HashSet fast unique, TreeSet sorted unique, LinkedHashSet ordered unique

Map

A Map stores key-value pairs. Keys are unique; values can repeat.

Maps are optimized for fast key-based lookup rather than sequential access.

Use a Map when you need to associate each key with one value, like id → student or country → capital.

Maps do not implement Collection, so they have their own APIs for keys, values, and entries.

HashMap (most used)

Provides fast average O(1) put/get using hashing. Order is not guaranteed and one null key is allowed.

When keys are well-distributed, HashMap gives near-constant time performance.

Prefer it for large datasets where ordering is not required.

import java.util.HashMap; HashMap grades = new HashMap<>(); grades.put("Alice", 92); grades.put("Bob", 85); grades.put("Charlie", 78); grades.put("Diana", 95); System.out.println(grades.get("Alice")); System.out.println(grades.get("Eve")); System.out.println(grades.getOrDefault("Eve", 0)); System.out.println(grades.containsKey("Bob")); System.out.println(grades.containsValue(78)); grades.put("Bob", 90); grades.remove("Charlie"); System.out.println(grades.size());

Iterating a HashMap

Use keySet for keys, values for values, and entrySet when you need both key and value together.

entrySet avoids repeated lookups and is best for performance when reading both.

forEach is concise for printing or simple processing.

for (String name : grades.keySet()) { System.out.println(name); } for (int grade : grades.values()) { System.out.println(grade); } for (Map.Entry entry : grades.entrySet()) { System.out.println(entry.getKey() + " → " + entry.getValue()); } grades.forEach((name, grade) -> System.out.println(name + ": " + grade));

TreeMap (sorted keys)

Maintains keys in sorted order using a balanced tree. Slower than HashMap but great for range queries.

Useful when you need sorted iteration, smallest/largest keys, or subMap ranges.

Keys must be comparable or you must supply a comparator.

import java.util.TreeMap; TreeMap prices = new TreeMap<>(); prices.put("Mango", 80); prices.put("Apple", 120); prices.put("Banana", 40); prices.put("Grapes", 150); System.out.println(prices); System.out.println(prices.firstKey()); System.out.println(prices.lastKey());

LinkedHashMap (insertion order)

Preserves insertion order and offers predictable iteration while keeping hashing performance.

Iteration order matches insertion order, which is useful for display or deterministic output.

Often used as a foundation for LRU cache logic.

import java.util.LinkedHashMap; LinkedHashMap capitals = new LinkedHashMap<>(); capitals.put("India", "New Delhi"); capitals.put("France", "Paris"); capitals.put("Japan", "Tokyo"); capitals.forEach((country, capital) -> System.out.println(country + " → " + capital));

Map Comparison

Pick based on ordering: HashMap for speed, TreeMap for sorted keys, LinkedHashMap for insertion order.

HashMap is usually fastest, TreeMap provides sorted access, LinkedHashMap gives stable iteration.

Key order → HashMap none, TreeMap sorted, LinkedHashMap insertion Performance→ HashMap fastest, TreeMap slower, LinkedHashMap slightly slower Null keys → HashMap one, TreeMap no, LinkedHashMap one Best for → HashMap fast lookup, TreeMap sorted keys, LinkedHashMap ordered keys

Collections Utility Class

Contains static helper methods for sorting, searching, reversing, and working with collections.

These algorithms operate on existing lists and can save you from writing common logic.

Binary search requires a sorted list, and reverseOrder helps in descending sorts.

import java.util.Collections; import java.util.ArrayList; ArrayList nums = new ArrayList<>(); nums.add(40); nums.add(10); nums.add(70); nums.add(25); nums.add(55); Collections.sort(nums); Collections.sort(nums, Collections.reverseOrder()); System.out.println(Collections.min(nums)); System.out.println(Collections.max(nums)); Collections.reverse(nums); Collections.shuffle(nums); ArrayList words = new ArrayList<>(); words.add("apple"); words.add("banana"); words.add("apple"); System.out.println(Collections.frequency(words, "apple")); ArrayList sorted = new ArrayList<>(); sorted.add(10); sorted.add(30); sorted.add(50); sorted.add(70); System.out.println(Collections.binarySearch(sorted, 50));

Stack (LIFO)

LIFO means last-in element is removed first. Common for undo history and backtracking.

Think of a stack of plates: you remove the top plate first.

push adds, pop removes, and peek reads the top without removing.

import java.util.LinkedList; LinkedList stack = new LinkedList<>(); stack.push("Page 1"); stack.push("Page 2"); stack.push("Page 3"); System.out.println("Stack: " + stack); System.out.println("Top: " + stack.peek()); System.out.println("Popped: " + stack.pop()); System.out.println("Stack: " + stack);

Queue (FIFO)

FIFO means first-in element is removed first. Used in scheduling, buffering, and messaging.

Queues model real-world lines where the earliest entry is served first.

offer adds to the tail, poll removes from the head, and peek inspects the head.

import java.util.LinkedList; import java.util.Queue; Queue queue = new LinkedList<>(); queue.offer("Customer 1"); queue.offer("Customer 2"); queue.offer("Customer 3"); System.out.println("Queue: " + queue); System.out.println("Next: " + queue.peek()); System.out.println("Served: " + queue.poll()); System.out.println("Queue: " + queue);

PriorityQueue (smallest first)

Always removes the highest-priority element (smallest by default). Useful for scheduling and shortest-path algorithms.

Unlike normal queues, order is based on priority, not insertion time.

Use a custom comparator for max-heap behavior.

import java.util.PriorityQueue; import java.util.Collections; PriorityQueue pq = new PriorityQueue<>(); pq.offer(50); pq.offer(10); pq.offer(30); pq.offer(5); pq.offer(20); while (!pq.isEmpty()) { System.out.print(pq.poll() + " "); } PriorityQueue maxPQ = new PriorityQueue<>(Collections.reverseOrder()); maxPQ.offer(50); maxPQ.offer(10); maxPQ.offer(30); System.out.println(maxPQ.poll());

Converting Between Collection Types

Conversions help when you need ordering, uniqueness, or a different API. For example, convert a List to a Set to remove duplicates, or a Set to a List for sorting.

Converting between types is common when a task needs a different collection behavior.

Remember that converting a List to a Set drops duplicates and may change order.

import java.util.*; String[] arr = {"Alice", "Bob", "Charlie"}; ArrayList list = new ArrayList<>(Arrays.asList(arr)); String[] backToArr = list.toArray(new String[0]); ArrayList withDups = new ArrayList<>(Arrays.asList(1, 2, 2, 3, 3, 3)); HashSet unique = new HashSet<>(withDups); ArrayList sortedList = new ArrayList<>(unique); Collections.sort(sortedList); ArrayList names = new ArrayList<>(Arrays.asList("Bob", "Alice", "Bob", "Charlie")); LinkedHashSet orderedUnique = new LinkedHashSet<>(names); HashMap scores = new HashMap<>(); scores.put("Charlie", 88); scores.put("Alice", 92); scores.put("Bob", 80); ArrayList keyList = new ArrayList<>(scores.keySet()); Collections.sort(keyList);

How HashMap Works Internally

HashMap uses hashCode() to place keys into buckets for O(1) average access.

When collisions happen, multiple keys share a bucket, so equals is used to find the correct one.

When the load factor threshold is reached, the map resizes and rehashes entries.

Good hashCode implementations distribute keys evenly to keep buckets small and fast.

Poor hashing causes long chains and slower access time.

When you put("Alice", 92): 1) hashCode() → number 2) bucket index computed 3) key-value stored in bucket Collisions → multiple keys in same bucket Load factor → 0.75 triggers resize (rehashing) Pre-size: new HashMap<>(1024) HashSet uses HashMap internally: set.add("Apple") → map.put("Apple", DUMMY_VALUE)

Advanced HashMap Methods

These methods reduce boilerplate by handling missing keys and updates in one step.

They are safer and more concise for counters, groupings, and default values.

computeIfAbsent is especially useful for building lists or sets of values per key.

HashMap votes = new HashMap<>(); votes.put("Alice", 5); int aliceVotes = votes.getOrDefault("Alice", 0); int bobVotes = votes.getOrDefault("Bob", 0); HashMap scores = new HashMap<>(); scores.put("Alice", 90); scores.putIfAbsent("Alice", 100); scores.putIfAbsent("Bob", 85); HashMap> groups = new HashMap<>(); groups.computeIfAbsent("Team B", k -> new ArrayList<>()).add("Bob"); groups.computeIfAbsent("Team B", k -> new ArrayList<>()).add("Charlie"); HashMap wordCount = new HashMap<>(); String[] words = {"apple", "banana", "apple", "cherry", "apple", "banana"}; for (String word : words) { wordCount.merge(word, 1, Integer::sum); }

Nested Collections

Nested collections model grouped or hierarchical data, such as a student mapped to a list of marks.

They are common in real applications but require careful iteration and null checks.

Think of it as a table: each key points to a collection of related values.

They are powerful for representing grouped data but can become complex, so keep structures consistent.

import java.util.*; HashMap> studentMarks = new HashMap<>(); studentMarks.put("Alice", new ArrayList<>(Arrays.asList(88, 92, 79))); studentMarks.put("Bob", new ArrayList<>(Arrays.asList(70, 65, 80))); studentMarks.get("Alice").add(95); for (Map.Entry> entry : studentMarks.entrySet()) { ArrayList marks = entry.getValue(); int sum = 0; for (int m : marks) sum += m; double avg = (double) sum / marks.size(); System.out.printf("%-8s | Marks: %-20s | Avg: %.1f%n", entry.getKey(), marks.toString(), avg); } HashMap> records = new HashMap<>(); HashMap aliceMarks = new HashMap<>(); aliceMarks.put("Math", 92); aliceMarks.put("Science", 88); aliceMarks.put("English", 79); records.put("Alice", aliceMarks); HashMap bobMarks = new HashMap<>(); bobMarks.put("Math", 75); bobMarks.put("Science", 80); bobMarks.put("English", 85); records.put("Bob", bobMarks); for (Map.Entry> student : records.entrySet()) { System.out.println("Student: " + student.getKey()); student.getValue().forEach((subject, mark) -> System.out.println(" " + subject + ": " + mark)); }

Unmodifiable Collections

Unmodifiable collections prevent changes through the returned view. Useful for read-only data and API safety.

List.of, Set.of, and Map.of create fixed collections that cannot be changed at all.

Unmodifiable views reflect changes in the original collection, but you cannot edit through the view.

Use them to protect internal data from accidental modification.

import java.util.Collections; ArrayList students = new ArrayList<>(); students.add("Alice"); students.add("Bob"); List readOnly = Collections.unmodifiableList(students); System.out.println(readOnly.get(0)); List fixed = List.of("Alice", "Bob", "Charlie"); Set fixedSet = Set.of("A", "B", "C"); Map fixedMap = Map.of("Alice", 90, "Bob", 85);
