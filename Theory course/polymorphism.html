Polymorphism

What is Polymorphism?

Polymorphism is the ability of an object to take on many forms. In Java, this means that a single method name or object reference can behave differently depending on the context in which it is used. It allows you to write flexible code that can work with objects of different types as if they were the same type. The two main types of polymorphism in Java are compile-time (handled by method overloading) and runtime (handled by method overriding).

  • Compile-time: Decisions are made by the compiler (e.g., Overloading).
  • Runtime: Decisions are made while the program is running (e.g., Overriding).

Compile-time Polymorphism — Method Overloading

Compile-time polymorphism, or method overloading, occurs when multiple methods in the same class share the same name but have different parameter lists. The compiler determines which method to call by matching the argument types and count to the method signatures. This allows you to perform similar operations (like adding numbers) on different data types without creating unique method names for each one. It improves code readability and reduces complexity.

public class Calculator { public int add(int a, int b) { return a + b; } public int add(int a, int b, int c) { return a + b + c; } public double add(double a, double b) { return a + b; } public String add(String a, String b) { return a + b; } }

Rules of Overloading

To successfully overload a method, you must change the parameter list. You can change the number of parameters, the types of parameters, or their order. However, changing only the return type or the access modifier is not sufficient to distinguish overloaded methods. If the compiler cannot find a unique match for a method call, it will report an ambiguity error.

What can differ What cannot differ
Number of parameters Return type alone
Type of parameters Parameter names only
Order of parameters

Practical Overloading Example

In this example, the `print` method is overloaded to handle different types of input: a string, a number, or an array of strings. The user of the class doesn't need to remember different method names like `printString` or `printInt`. They simply call `print`, and Java automatically routes the call to the correct implementation. This pattern is very common in standard Java libraries, such as `System.out.println()`.

public class Printer { public void print(String message) { System.out.println(message); } public void print(String message, int times) { for (int i = 0; i < times; i++) System.out.println(message); } public void print(int number) { System.out.println("Number: " + number); } public void print(String[] items) { for (String item : items) System.out.println("- " + item); } }

Overloading vs Overriding

It is crucial to understand the difference between these two concepts. Overloading happens within the same class and is resolved at compile time based on method signatures. Overriding happens in a subclass and is resolved at runtime based on the actual object type. Overloading increases the readability of methods, while overriding allows for specific implementations of inherited behavior.

Feature Overloading Overriding
Where Same class Child class
Parameters Must differ Must be same
Decided at Compile time Runtime
Keyword None @Override

Runtime Polymorphism

Runtime polymorphism allows a reference variable of a parent class to hold an object of a child class. When a method is called on this reference, Java looks at the actual object in memory to decide which method to execute. This is also known as dynamic method dispatch. It is the mechanism that allows generic code (like a list of `Animal`s) to behave specifically for each object (like `Dog`s barking and `Cat`s meowing).

public class Animal { String name; public Animal(String name) { this.name = name; } public void makeSound() { System.out.println(name + " makes a sound."); } } public class Dog extends Animal { public Dog(String name) { super(name); } @Override public void makeSound() { System.out.println(name + " barks: Woof!"); } }

Dynamic Method Dispatch

This example demonstrates how the same reference variable `a` can point to different objects at different times. First, it points to a `Dog`, so calling `makeSound()` prints "Woof". Later, it points to a `Cat`, and the same line of code prints "Meow". The decision of which method to run is deferred until the program is actually running, hence the name "dynamic dispatch".

Animal a; a = new Dog("Rex"); a.makeSound(); a = new Cat("Whiskers"); a.makeSound();

The variable type is Animal, but Java calls the child method based on the real object.

Upcasting and Downcasting

Upcasting is treating a child object as a parent object, which is always safe and happens automatically. Downcasting is converting a parent reference back to a child reference, which requires an explicit cast. Downcasting can be dangerous if the object is not actually of that child type, leading to a `ClassCastException`. You should always use the `instanceof` operator to check the type before downcasting.

Dog dog = new Dog("Rex"); Animal a = dog; Animal a2 = new Cat("Whiskers"); Dog d2 = (Dog) a2;

Upcasting is automatic and safe. Downcasting must be checked with instanceof.

Method Hiding vs Overriding

Static methods cannot be overridden; they can only be hidden. If a child class defines a static method with the same signature as one in the parent, the child's method hides the parent's. Unlike instance methods, the version of the static method that gets called is determined by the class of the reference variable, not the actual object. This is a common source of confusion, so it's best to access static methods via the class name directly.

public class Animal { public static void info() { System.out.println("I am Animal"); } public void speak() { System.out.println("..."); } } public class Dog extends Animal { public static void info() { System.out.println("I am Dog"); } @Override public void speak() { System.out.println("Woof"); } } Animal a = new Dog("Rex"); a.info(); a.speak();

Full Example: Payment System

This comprehensive example shows polymorphism in a real-world scenario. We define a base `Payment` class and several subclasses like `CreditCard`, `UPI`, and `Cash`. We can then create a single array of `Payment` objects that contains a mix of these different types. The `process()` loop treats them all as `Payment`s, but each one executes its own specific processing logic.

public class Payment { protected String sender; protected double amount; public Payment(String sender, double amount) { this.sender = sender; this.amount = amount; } public void process() { System.out.println(sender + " pays $" + amount); } public String getType() { return "Unknown"; } @Override public String toString() { return getType() + " | " + sender + " | $" + amount; } } public class CreditCard extends Payment { private String cardNumber; public CreditCard(String sender, double amount, String cardNumber) { super(sender, amount); this.cardNumber = cardNumber; } @Override public void process() { System.out.println("Credit card charged: " + cardNumber + " for $" + amount); } @Override public String getType() { return "CreditCard"; } } public class UPI extends Payment { private String upiId; public UPI(String sender, double amount, String upiId) { super(sender, amount); this.upiId = upiId; } @Override public void process() { System.out.println("UPI transfer via " + upiId + " for $" + amount); } @Override public String getType() { return "UPI"; } } public class Cash extends Payment { public Cash(String sender, double amount) { super(sender, amount); } @Override public void process() { System.out.println("Cash payment of $" + amount + " received."); } @Override public String getType() { return "Cash"; } } Payment[] payments = { new CreditCard("Alice", 250.00, "****-1234"), new UPI("Bob", 150.00, "bob@upi"), new Cash("Charlie", 50.00), new UPI("Diana", 300.00, "diana@upi") }; double total = 0; for (Payment p : payments) { p.process(); total += p.amount; } System.out.println("\nTotal collected: $" + total);

Benefits of Polymorphism

Polymorphism makes your code more modular and easier to extend. You can add new classes (like a `Bitcoin` payment method) without changing the existing code that processes payments. It simplifies code by allowing you to treat related objects uniformly. This reduces code duplication and separates the "what" (the interface) from the "how" (the implementation).

Benefit Explanation
Extensibility Add new types without changing existing code
Simplicity One loop handles all types
Flexibility Swap objects at runtime
Maintainability Logic stays in each class

Common Mistakes

One common mistake is trying to call a child-specific method on a parent reference without downcasting. Another is assuming that static methods work like instance methods (they don't override). Confusing overloading (same class) with overriding (subclass) is also frequent. The snippets below illustrate these traps so you can avoid them.

Animal a = new Dog("Rex"); a.bark(); ((Dog) a).bark(); Animal a2 = new Cat("Whiskers"); Dog d2 = (Dog) a2; if (a2 instanceof Dog) { Dog d = (Dog) a2; } public void show(int n) { } public void show(String s) { } @Override public void show(int n) { }

Quick Reference

This section provides a quick look at the syntax for overloading, overriding, and casting. Use it to refresh your memory on the keywords and structures. Remember that `@Override` is optional but recommended, and `instanceof` is your safety net for casting. Keep these patterns in mind when designing your class hierarchies.

void add(int a, int b) { } void add(double a, double b) { } class Dog extends Animal { @Override public void makeSound() { } } Animal a = new Dog("Rex"); if (a instanceof Dog) { Dog d = (Dog) a; } Animal[] arr = { new Dog(), new Cat(), new Bird() }; for (Animal x : arr) { x.makeSound(); }
