Serialization

What is Serialization?

Serialization converts a Java object into a byte stream so it can be saved, sent over a network, or stored in a database.

Deserialization rebuilds the original object from the byte stream.

This allows objects to be persisted or transferred while preserving their state.

Only the object’s data is stored, not its behavior or methods.

Object → (Serialization) → Byte Stream → File / Network File → (Deserialization) → Byte Stream → Object

Making a Class Serializable

A class must implement Serializable (marker interface) to be serialized.

Serializable has no methods; it simply tells the JVM the class can be serialized.

All non-transient fields must also be serializable, or you will get errors.

import java.io.Serializable; public class Student implements Serializable { private static final long serialVersionUID = 1L; private String name; private int age; private String grade; public Student(String name, int age, String grade) { this.name = name; this.age = age; this.grade = grade; } public String getName() { return name; } public int getAge() { return age; } public String getGrade() { return grade; } @Override public String toString() { return "Student{name='" + name + "', age=" + age + ", grade='" + grade + "'}"; } }

serialVersionUID is the class version. If it changes, old files fail with InvalidClassException.

Define it explicitly to keep backward compatibility across code changes.

Writing an Object to a File

ObjectOutputStream converts the object graph into bytes and writes them to a file.

The whole object graph is serialized, including referenced objects, if they are serializable.

import java.io.*; public class WriteObject { public static void main(String[] args) { Student student = new Student("Alice", 20, "A"); try (FileOutputStream fos = new FileOutputStream("student.ser"); ObjectOutputStream oos = new ObjectOutputStream(fos)) { oos.writeObject(student); System.out.println("Object saved: " + student); } catch (IOException e) { e.printStackTrace(); } } }

Writing Multiple Objects

The easiest way is to serialize a collection like ArrayList, which preserves order.

When reading, you cast back to the same collection type.

import java.io.*; import java.util.ArrayList; public class WriteMultiple { public static void main(String[] args) { ArrayList students = new ArrayList<>(); students.add(new Student("Alice", 20, "A")); students.add(new Student("Bob", 22, "B")); students.add(new Student("Charlie", 21, "A")); try (ObjectOutputStream oos = new ObjectOutputStream( new FileOutputStream("students.ser"))) { oos.writeObject(students); System.out.println("Saved " + students.size() + " students."); } catch (IOException e) { e.printStackTrace(); } } }

What Gets Serialized?

Instance fields are serialized by default. static fields belong to the class, not the object, so they are not saved.

transient fields are skipped, which is useful for sensitive or derived data.

public class Example implements Serializable { private String name; // serialized private int age; // serialized static int count = 0; // not serialized transient String password; // not serialized }

.ser .dat .obj

Reading an Object from a File

ObjectInputStream reconstructs the object graph from the byte stream.

readObject returns Object, so you must cast it to the correct type.

import java.io.*; public class ReadObject { public static void main(String[] args) { try (FileInputStream fis = new FileInputStream("student.ser"); ObjectInputStream ois = new ObjectInputStream(fis)) { Student student = (Student) ois.readObject(); System.out.println("Loaded: " + student); } catch (IOException | ClassNotFoundException e) { e.printStackTrace(); } } }

The transient Keyword

Use transient for sensitive or derived fields so they are skipped during serialization.

After deserialization, transient fields get default values like null or 0.

This is useful for passwords, computed fields, or resources that cannot be serialized.

import java.io.Serializable; public class User implements Serializable { private static final long serialVersionUID = 1L; private String username; private String email; private transient String password; public User(String username, String email, String password) { this.username = username; this.email = email; this.password = password; } @Override public String toString() { return "User{username='" + username + "', email='" + email + "', password='" + password + "'}"; } }

Serialization Versioning

Versioning controls whether old serialized data can be read by a newer class definition.

If serialVersionUID stays the same, new fields will get default values on load.

public class Student implements Serializable { private static final long serialVersionUID = 1L; private String name; private int age; } public class Student implements Serializable { private static final long serialVersionUID = 1L; private String name; private int age; private String grade; }

Keep serialVersionUID the same to allow old files to load. New fields get default values.

Changing the UID signals a breaking change and will invalidate old files.

Exceptions in Serialization

Most errors come from missing Serializable, version mismatches, or missing classes.

Full Example: Student Record System

import java.io.*; import java.util.*; public class StudentRecord { private static final String FILE = "records.ser"; public static void saveAll(ArrayList list) { try (ObjectOutputStream oos = new ObjectOutputStream( new FileOutputStream(FILE))) { oos.writeObject(list); System.out.println("Saved " + list.size() + " records."); } catch (IOException e) { System.out.println("Save failed: " + e.getMessage()); } } @SuppressWarnings("unchecked") public static ArrayList loadAll() { File f = new File(FILE); if (!f.exists()) return new ArrayList<>(); try (ObjectInputStream ois = new ObjectInputStream( new FileInputStream(FILE))) { return (ArrayList) ois.readObject(); } catch (IOException | ClassNotFoundException e) { System.out.println("Load failed: " + e.getMessage()); return new ArrayList<>(); } } public static void main(String[] args) { ArrayList students = loadAll(); students.add(new Student("Alice", 20, "A")); students.add(new Student("Bob", 22, "B")); students.add(new Student("Charlie", 21, "A")); saveAll(students); ArrayList loaded = loadAll(); System.out.println("\n=== All Students ==="); loaded.forEach(System.out::println); } }

Custom Serialization — writeObject/readObject

Custom serialization lets you control what gets written and read for sensitive or computed data.

Use defaultWriteObject and defaultReadObject to keep standard behavior intact.

import java.io.*; public class SecureUser implements Serializable { private static final long serialVersionUID = 1L; private String username; private transient String password; public SecureUser(String username, String password) { this.username = username; this.password = password; } private void writeObject(ObjectOutputStream oos) throws IOException { oos.defaultWriteObject(); String encrypted = "ENC:" + password; oos.writeObject(encrypted); } private void readObject(ObjectInputStream ois) throws IOException, ClassNotFoundException { ois.defaultReadObject(); String encrypted = (String) ois.readObject(); this.password = encrypted.replace("ENC:", ""); } @Override public String toString() { return "SecureUser{username='" + username + "', password='" + password + "'}"; } }
SecureUser user = new SecureUser("alice", "secret123"); try (ObjectOutputStream oos = new ObjectOutputStream( new FileOutputStream("secure.ser"))) { oos.writeObject(user); System.out.println("Saved: " + user); } try (ObjectInputStream ois = new ObjectInputStream( new FileInputStream("secure.ser"))) { SecureUser loaded = (SecureUser) ois.readObject(); System.out.println("Loaded: " + loaded); }
